# Category 5: Enterprise Document & Lifecycle Automation

Operating manuals (`SKILL.md` blueprints) governing how worker/executor
models ingest enterprise documents and run disciplined, verifiable
execution lifecycles: extract densely, verify from fresh context, execute
without friction, and let tests lead the code.

| Skill | Purpose |
| --- | --- |
| [`dense-doc-extraction`](dense-doc-extraction/SKILL.md) | Convert long specs, raw PDFs, and architecture manuals into hyper-dense structured markdown — mental models, rules tables, checklists, and anti-pattern registers instead of loose prose summaries. |
| [`fresh-context-verification`](fresh-context-verification/SKILL.md) | Freeze at designated execution checkpoints, spin up an isolated cold-context verification sub-agent, and cross-examine real outputs directly against the original master spec. |
| [`zero-friction-execution`](zero-friction-execution/SKILL.md) | Operational efficiency doctrine for worker models — no conversational fluff, prompt loops, or unnecessary menus; execute the moment sufficient context exists, with a narrow escalation gate for genuine stops. |
| [`tdd-first-enforcement`](tdd-first-enforcement/SKILL.md) | Advanced TDD enforcement — mock fixtures, integration test configuration, and intentionally failing edge-case assertions must exist and be proven red before any functional code is generated. |
